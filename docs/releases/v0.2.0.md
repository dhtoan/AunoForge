# AunoForge v0.2.0

AunoForge v0.2 focuses on making evidence-aware review practical inside GitHub while preserving read-only defaults and human-controlled repository writes.

## GitHub Action runtime

- Ships the checked-in GitHub Action runtime on **Node 24**.
- Consumer repositories run the packaged Action without installing AunoForge dependencies or compiling the monorepo during each invocation.
- CI verifies generated runtime drift across the supported quality matrix.

## GitHub-native review output

- Adds a concise **GitHub Step Summary** with recommendation, provider/mode, severity counts, verification counts, report path, and annotation status.
- Keeps full reports available through `report-path` and supports optional workflow-layer artifact upload without enabling repository writes.

## Structured reports and annotations

- Supports Markdown, JSON, and **SARIF 2.1.0** review output from the same normalized review result.
- Adds bounded, diff-scoped GitHub workflow annotations only for evidence-verified actionable findings.
- Keeps the default annotation threshold at medium and the default cap at 25, with overflow represented in the report/summary instead of silently dropped.

## Incremental evidence review

- Adds stable finding fingerprints and explicit baseline comparison for **incremental** review.
- Classifies findings as `new`, `persistent`, `resolved`, or `regressed` without destructively filtering the complete current report.
- Accepts an explicit prior AunoForge JSON report as the baseline; AunoForge core does not remotely store or auto-discover baseline state.
- With a baseline supplied, Step Summary and annotations prioritize newly introduced and regressed evidence.

## Stable-install proof

- Adds a verified `v0.1.0` stable Action smoke path and a README output excerpt produced by the real stable Action.
- Separates published stable-tag examples from current-main / upcoming v0.2 examples so documentation does not imply unreleased features are available from the stable tag.

## Safety boundaries retained

- Repository writes remain disabled by default.
- PR comments still require explicit write opt-in and appropriate GitHub permission.
- No auto-merge, release publication, Marketplace publication, package update, or dependency remediation is performed automatically.
