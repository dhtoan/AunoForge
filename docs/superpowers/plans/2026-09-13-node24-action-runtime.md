# Node 24 GitHub Action Runtime Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade the packaged AunoForge GitHub Action runtime from Node 20 to Node 24 without changing the local CLI's Node.js 20+ compatibility policy or weakening the Action's least-privilege behavior.

**Architecture:** Keep the existing checked-in JavaScript Action packaging introduced by PR #9. Change only the GitHub Action runtime contract and generated bundle target to Node 24, prove the old Node 20 contract fails first, regenerate `dist/action/`, and use the existing `uses: ./` smoke workflow plus generated-runtime drift checks as the integration gate. The local CLI continues to be tested on Node 20/22/24.

**Tech Stack:** GitHub Actions JavaScript Action metadata, Node.js 24 runtime, Node.js built-in test runner, esbuild 0.28.2, pnpm 10.15.1, TypeScript monorepo, GitHub Actions CI.

**Spec:** `docs/superpowers/specs/2026-09-13-github-native-evidence-review-platform-design.md`

## Global Constraints

- Maintain exactly one maintainer-generated primary upgrade PR at a time; apply this plan to existing PR #9 branch `feat/v0.2-packaged-action-runtime`.
- No auto-merge.
- Read-only behavior remains the default.
- Any GitHub write requires explicit configuration and minimum required permission.
- Fork-originated pull requests must never gain an implicit write path.
- Provider credentials remain optional unless a network provider is explicitly selected.
- Deterministic/mock mode remains a first-class zero-key path.
- Local CLI support remains Node.js 20+; this plan changes only the GitHub-hosted Action runtime contract and Action bundle target.
- CI keeps the Node 20/22/24 quality matrix and macOS/Windows CLI smoke coverage.
- Generated `dist/action/` files are rebuilt from source and never hand-edited.
- Behavior-changing work follows RED -> GREEN verification before completion claims.
