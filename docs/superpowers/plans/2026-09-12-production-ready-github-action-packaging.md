# Production-Ready GitHub Action Packaging Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace AunoForge's install-and-build-on-every-run composite Action with a checked-in, reproducibly generated Node 20 Action runtime that downstream repositories can execute without `pnpm install` or TypeScript compilation.

**Architecture:** Keep `action.yml` as the public interface, but change it from `runs.using: composite` to a JavaScript Action using GitHub's `node20` runtime. Build two committed runtime files under `dist/action/`: `index.mjs` for the Action entry point and `cli.mjs` for the bundled AunoForge CLI. `index.mjs` keeps the existing input validation/report-file/write-boundary behavior and spawns `cli.mjs` with `process.execPath`; the runtime is generated by esbuild from maintained source and CI rejects generated-runtime drift.

**Tech Stack:** Node.js 20+, TypeScript/NodeNext, pnpm 10.15.1, Node test runner, esbuild, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-12-v0.2-star-worthy-growth-design.md`

## Global Constraints

- Node.js development floor remains **20+**.
- Package manager remains **pnpm 10.15.1**.
- The public Action continues to support `command=review` only in this milestone.
- `provider=mock` remains the default and must make no external model request.
- `comment=false` remains the default.
- `comment=true` still requires `allow-write=true` and `pull-requests: write`.
- No automatic merge, release publication, issue mutation, or unrelated GitHub write is introduced.
- Downstream Action execution must perform **no dependency install** and **no TypeScript/source compilation** inside the consumer repository.
- `report-path` remains a public Action output.
- Existing Node 20/22/24 quality coverage and macOS/Windows CLI smoke coverage remain intact.
- Generated runtime is committed intentionally; `packages/*/dist/` remains ignored development output.
- Do not update README stable-tag examples in this PR; that belongs to the later 60-second-proof PR.
- Do not implement Step Summary, sticky comments, or Marketplace metadata in this PR; those are later v0.2 milestones.

## File Structure

The implementation should touch only the packaging/runtime surface plus tests and contributor guidance:

- `action.yml` — public GitHub Action metadata; switches from composite steps to `node20` + `dist/action/index.mjs`.
- `scripts/action.mjs` — maintained Action entry source; resolves the packaged CLI at `dist/action/cli.mjs` and preserves current validation/report/write behavior.
- `scripts/build-action.mjs` — new deterministic bundler entry; builds `scripts/action.mjs` and `packages/cli/dist/bin.js` into committed Action runtime files.
- `dist/action/index.mjs` — generated bundled Action entry; committed.
- `dist/action/cli.mjs` — generated bundled CLI runtime; committed.
- `package.json` — adds Action build/verification scripts and pinned esbuild development tooling.
- `pnpm-lock.yaml` — new lockfile generated by pnpm 10.15.1 so Action build tooling is reproducible.
- `test/action-manifest.test.mjs` — expands metadata contract checks to forbid install/build work in downstream execution.
- `test/action-runtime.test.mjs` — new packaged-runtime smoke test using mock mode and a deterministic diff.
- `.github/workflows/ci.yml` — uses frozen installs and verifies generated runtime is current.
- `.github/workflows/aunoforge-review.yml` — exercises the packaged Action itself for Markdown and JSON instead of relying on source `packages/*/dist` created by the old composite build step.
- `CONTRIBUTING.md` — documents the generated Action runtime workflow for contributors.

No core review algorithm, provider protocol, finding schema, recipe contract, or reporter output format changes in this PR.

- [ ] **Step 2: Add a packaged CLI smoke test that proves mock review works without provider credentials**

Create `test/action-runtime.test.mjs` with a deterministic diff fixture written into a temporary directory:

```js
import assert from 'node:assert/strict';
import test from 'node:test';
import { mkdtemp, rm, writeFile } from 'node:fs/promises';
import { spawn } from 'node:child_process';
import { join } from 'node:path';
import { tmpdir } from 'node:os';

function runNode(args, options = {}) {
  return new Promise((resolve, reject) => {
    const child = spawn(process.execPath, args, {
      ...options,
      stdio: ['ignore', 'pipe', 'pipe'],
    });
    let stdout = '';
    let stderr = '';
    child.stdout.on('data', (chunk) => { stdout += chunk; });
    child.stderr.on('data', (chunk) => { stderr += chunk; });
    child.on('error', reject);
    child.on('close', (code) => resolve({ code, stdout, stderr }));
  });
}

test('packaged cli runs a zero-key deterministic mock review', async () => {
  const root = await mkdtemp(join(tmpdir(), 'aunoforge-action-runtime-'));
  try {
    const diffPath = join(root, 'change.diff');
    await writeFile(diffPath, [
      'diff --git a/src/example.js b/src/example.js',
      '--- a/src/example.js',
      '+++ b/src/example.js',
      '@@ -0,0 +1 @@',
      '+eval(userInput);',
      '',
    ].join('\n'));

    const runtime = new URL('../dist/action/cli.mjs', import.meta.url);
    const result = await runNode([
      runtime.pathname,
      'review',
      '--root', root,
      '--provider', 'mock',
      '--format', 'json',
      '--diff', diffPath,
    ], {
      cwd: root,
      env: {
        ...process.env,
        OPENAI_API_KEY: '',
        ANTHROPIC_API_KEY: '',
      },
    });

    assert.equal(result.code, 0, result.stderr);
    const report = JSON.parse(result.stdout);
    assert.ok(report.findings.some((finding) => finding.category === 'javascript-eval'));
  } finally {
    await rm(root, { recursive: true, force: true });
  }
});
```

During implementation, use `fileURLToPath(runtime)` instead of `runtime.pathname` if the Windows platform smoke run is extended to this test. The initial test runs in the Ubuntu quality job; the packaged CLI itself is separately exercised cross-platform by the existing CLI matrix.

- [ ] **Step 3: Create `scripts/build-action.mjs`**

Use esbuild's JavaScript API so the build is cross-platform and shell-independent:

```js
import { build } from 'esbuild';
import { mkdir, rm } from 'node:fs/promises';
import { resolve } from 'node:path';

const root = resolve(new URL('..', import.meta.url).pathname);
const outdir = resolve(root, 'dist', 'action');

await rm(outdir, { recursive: true, force: true });
await mkdir(outdir, { recursive: true });

const shared = {
  bundle: true,
  platform: 'node',
  format: 'esm',
  target: 'node20',
  sourcemap: false,
  legalComments: 'none',
  logLevel: 'info',
};

await build({
  ...shared,
  entryPoints: [resolve(root, 'scripts', 'action.mjs')],
  outfile: resolve(outdir, 'index.mjs'),
});

await build({
  ...shared,
  entryPoints: [resolve(root, 'packages', 'cli', 'dist', 'bin.js')],
  outfile: resolve(outdir, 'cli.mjs'),
});
```

Use `fileURLToPath(new URL('..', import.meta.url))` rather than `.pathname` in the final implementation so Windows drive-letter paths are correct:

```js
import { fileURLToPath } from 'node:url';
const root = resolve(fileURLToPath(new URL('..', import.meta.url)));
```

### Type/interface consistency
